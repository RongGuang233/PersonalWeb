# RongGuang233 个人网站

Python 3.10+ 标准库、SQLite、原生 HTML/CSS/JS。浏览器 Markdown 使用 MIT 许可的 Marked、KaTeX 和 marked-katex-extension，自托管脚本、样式与公式字体；服务器无需 Node 或第三方 Python 依赖。package.json 声明浏览器运行依赖，package-lock.json 记录当前解析版本。维护该资源时使用 Node 20+，执行 npm ci、npm run vendor:markdown；浏览器不请求外部 CDN。

首页采用浅色导航、个人身份卡和近况三栏布局；手机端压缩介绍卡，让栏目入口优先露出。头像、简介、背景和近况均来自本站数据，不填充示例记录。首页显示最新两条公开博客、笔记、项目或作品，可额外推荐一篇精选文章（优先置顶，总数最多三条）；时钟在手机端放在近况之后。内容页提供博客、笔记、项目、六类作品、友链、收藏和搜索，使用系统无衬线字体，支持浅色/深色外观与减少动态效果偏好。项目栏目用封面卡片墙展示工具、网站等个人作品，详情支持 Markdown、技术标签、状态、仓库与演示链接。

公开页和管理页均支持作品名称、短评和进度搜索，保留五颗星和数字评分。公开作品页按动画、漫画、游戏、小说、书籍、影视分区，每区先展示 8 部，区标题旁是随分类变化的动词胶囊（动画/影视「在看·看过·想看」、漫画/小说/书籍「在读·读过·想读」、游戏「在玩·玩过·想玩」）以及「N 部 · 均分」。数量为零的胶囊保留但弱化且不可点。默认按评分从高到低排列；切到「最近更新」后该选择写入网址，刷新与翻页都会保留。筛选条吸顶且不透明；筛选状态用一行面包屑表示当前位置（`作品记录 / 动画 / 看过`，金色斜线分隔，最后一项为当前项），第一段「作品记录」就是回到全部作品的入口，因此不再提供可逐个删除的筛选标签，搜索结果则显示为 `作品记录 / 搜索“关键词”`。分页每页 24 部并以胶囊条显示「第 x / y 页」。缺少封面时按分类给出不同色相的首字占位，图片加载失败约 3 秒后也回退到该占位；作品详情给出三个相近作品。筛选及搜索条件写入网址，浏览器返回和页面内返回列表可恢复阅读位置。文章正文为 17px，首图限制高度，长文（至少 1,500 字符且含三个二/三级标题）显示目录：宽屏在正文旁保留侧栏，手机和较窄窗口在滚过原目录后出现快捷目录，支持章节跳转、Esc 和点击外部关闭。文末提供复制链接和下一篇，宽公式只在公式区域内横向滚动。

正文里的一级标题在渲染时降为二级，因此每页只保留一个 H1（页面标题），正文层级和目录结构不受影响。

浅色主题的页面底色比卡片深一档，卡片是白底加细边和一层柔和投影，因此列表、知识地图和作品墙都能看出卡片边界；博客列表和笔记列表另用左侧色脊区分（博客金色、笔记蓝色），阅读页是浮在底色上的一张纸。深色主题沿用同一套层次。外观默认跟随系统偏好：`theme-init.js` 在首次绘制前写入主题（`<head>` 中的非延迟脚本，因为 CSP 禁止内联脚本），避免深色用户看到一闪而过的浅色；手动切换后以本地记录为准，并不再跟随系统。

公开搜索优先展示标题匹配，并摘取命中位置附近的正文片段、高亮关键词。可按博客、笔记、作品、友链、收藏限定类型，每项显示匹配数量；关键词和类型均写入网址，返回列表时恢复。从搜索进入阅读时，“下一个结果”只在本次关键词及类型对应的结果内前进，最后一条不显示下一篇。

内容管理增加“全部范围／已公开／仅自己可见”筛选，可与关键词及作品分类组合，并随网址恢复；草稿仍在独立区域展示。按作品分类浏览时，新增作品继承当前分类（其次记住上次保存时选择的分类），不改变默认公开设置。作品编辑表单的分类是模块按钮，状态下拉的动词跟随所选分类（例如从动画切到游戏，选项由“在看/看过/想看”变为“在玩/玩过/想玩”，并保留原来选的档位）；新增作品的状态默认是该分类的完成态（看过／读过／玩过），而不是“想看”。友链管理列表直接展示当前头像及顺序数字，数字越小越靠前。

博客列表和文章详情的标签可以点击，进入 `#posts?tag=主题` 对应的公开文章列表；显示当前主题、数量及清除入口，下一篇也限制在该主题内。标签按中文逗号、英文逗号或换行分隔，去除空项及重复项，标签内空格保留；不重写已有标签数据。

笔记也支持可选主题标签，公开笔记页会根据真实标签生成知识地图；没有标签的旧笔记继续正常显示。分类切换只有一条导航（纯文字标签页，当前分类加粗并带一条金色短线），进入某个分类后不会再出现第二条分类导航；分类页只保留「分类目录 + 篇数」这一个当前位置说明。笔记编辑器支持拖入或选择 `.md` 文件，自动提取首个一级标题、正文和 front matter 中的 `tags`，导入内容先进入现有私密草稿流程，发布规则保持不变。

笔记阅读页提供分层章节目录、阅读位置返回、可横向滚动的宽公式和表格，以及支持键盘操作的图片预览。相同标题、分类与正文仅有图片链接差异的重复笔记，在首页、目录和搜索中优先显示本地配图可用的一份；原始记录保留。同名但正文不同的笔记分别展示。

在“私人空间 → 作品记录 → 分类公开设置”中可隐藏或恢复动画、漫画、游戏、小说、书籍、影视任一大类。隐藏后该类作品停止出现在公开首页、列表、搜索、详情与封面访问中，管理页保留记录并标注“分类已隐藏”。恢复时沿用各条作品原来的公开状态，不批量改写记录。

## 内容与头像

点击“私人空间”并登录后，入口显示为“内容管理”，可管理内容与个人资料。首页和内容页的“写点什么”可直接写博客、写笔记或记录作品，并进入汇总博客与笔记的“继续草稿”。手机内容页将品牌与操作合为首行，栏目导航置于第二行；“＋”打开写作菜单。手机端管理导航默认收起为当前栏目，可点“切换栏目”展开；写作菜单支持 Esc 和点击外部关闭。登录后公开文章、笔记、作品详情提供“编辑此篇”，内容管理提供“个人资料”；快捷编辑会读取最新内容，发布后原阅读页即时更新。新增博客、笔记、作品、友链和收藏默认公开，勾选“仅自己可见”后保存为私密。自动保存的草稿仍仅自己可见，点击发布按钮后才公开。已有记录与恢复的草稿保留原公开设置；编辑内容时，省略公开状态会保留原状态。

博客、笔记使用宽版编辑窗口，标题之后先放发布设置（默认展开），正文编辑区在下方；支持编辑/预览切换和字符计数；草稿状态和保存草稿入口移至标题栏。封面、摘要、发表日期及公开范围在发布设置中。保存按钮固定在窗口底部，并显示保存后的可见范围。正文最多 50,000 个 Unicode 字符（包括 emoji）；超限时会提示修改。后台文章列表显示摘要与编辑入口，公开页保留全文。从管理列表查看公开页后，可返回原管理列表，恢复搜索、作品筛选和滚动位置。

博客、笔记分别保存发表日期与更新时间；首次公开时自动记录发表日期，之后编辑只刷新更新时间。公开列表按发表日期排列，首页“最近更新”仍反映修改。旧公开记录沿用原更新时间作为暂存的发表日期，不推测真实历史日期；所有者可在发布设置中校正。校正先保存为私密草稿，提交正式内容后才生效，日期留空保留原日期。填写未来日期不代表预约发布。

公开文章、笔记和作品使用 `/read/posts/ID`、`/read/notes/ID`、`/read/works/ID` 独立地址；复制链接不会携带管理路径。服务器直接输出对应标题、摘要、canonical 和 Open Graph 元信息，优先使用该记录封面，其次使用已上传头像；私密或不存在的详情返回 404。生产环境应配置正确的 `SITE_ORIGIN`，供绝对分享地址与图片地址使用。实际分享卡片取决于平台抓取与缓存；域名上线前继续保留 noindex。

博客和笔记停止输入约 0.7 秒后自动保存到服务器私密草稿，可无标题保存；关闭编辑器会先完成保存。私人列表和统一“继续草稿”页使用相同的草稿卡片，区分“尚未发布”和“已有内容的修改”，均支持恢复、确认后丢弃；跨浏览器登录后也可继续。编辑已公开内容时，正文、封面、精选和公开设置均先进入草稿，只有点击“发布内容/更新公开内容/保存为私密内容”才提交到正式记录。丢弃草稿不改变原正式记录。网络或会话失败会保留当前输入并提示重试，不关闭编辑器；刷新/关闭标签页对尚未保存输入使用浏览器离开提醒。其他内容、资料和待上传图片仍使用明确保存及离开提醒。

关于我用「紧凑名片 + 阅读式分节」排布：顶部是一张约 170px 高的名片（头像、姓名、身份胶囊、首页简介、联系方式），下面依次是「正在整理的知识」「在看的」「在做的小东西」三个由站内数据自动生成的板块，以及一行「这个小站从 … 开始记录」和数据统计。这些板块只在有内容时才出现，不需要另外写文案页面就不会空；「个人资料」里的详细介绍会作为正文排在名片之后。

联系方式从「关于我」正文里自动识别：`QQ：123456` 和 `邮箱：you@example.com` 各生成一个可点击复制的胶囊，其余行按顺序排成正文段落；第一个短行作为身份胶囊，以「欢迎」开头的一行作为联系方式的说明文字。

在“私人空间 → 个人资料”中编辑名称、首页简介和独立的“关于我”详细介绍；详细介绍支持 Markdown、即时预览，最多 20,000 个 Unicode 字符，保存后公开展示并包含在完整导出中。旧资料迁移保留原名称、简介和图片，详细介绍留空时继续展示原简介。点击“选择图片”，查看圆形预览后点击“保存头像”，也可取消更换或恢复默认。浏览器支持 10 MB 以内的 PNG、JPEG、WebP 图片，可拖动、缩放、重置裁剪，确认后以 512 × 512 像素 PNG 上传；服务器接收最多 1 MiB 的 PNG。头像保存在 SQLite 中，重启后保留。名称、简介和头像会展示在公开首页；恢复默认后显示字母占位头像。

作品编辑优先显示进度、评分和短评；封面设置默认折叠，有封面时保留小预览，名称搜索的候选数量显示在折叠标题上。博客和作品可在新增/编辑时选择封面；源图支持 PNG、JPEG、WebP，最大 8 MB，浏览器按最长边 1200 像素压缩为 JPEG。服务器接收最多 2 MiB 的封面，存于 SQLite 的 `record_covers` 表；仅公开记录的封面允许匿名读取。替换不保留旧图，删除记录同步删除封面。

作品编辑器在输入名称停顿后按所选分类搜索候选封面，也可点击“搜索封面”手动重试。候选展示名称、版本信息与来源链接；点选仅替换待保存的封面，不改动名称、评分、进度或公开状态，点击“保存”后才写入原封面表。封面搜索与图片读取仅登录者可用，来源未收录或不可用时仍可手动上传。搜索不会批量补齐已有作品。动漫使用 Bangumi 公开检索（中文名通常可用），失败时回退豆瓣影视；影视使用豆瓣影视，漫画、小说、出版书籍使用豆瓣图书公开检索，游戏使用 Steam 商店公开检索，无需 API 密钥。图书候选可能混有同名版本，需要手动核对；游戏仅覆盖 Steam 收录范围。作品与文章封面支持截屏后粘贴（对话框内 Ctrl/Cmd+V，或点「粘贴封面」）。公开网页检索接口可能变更或限流，无法获取时保留手动上传。图片由服务器按需读取，选定后由浏览器压缩为 JPEG，保存后使用本站图片，不依赖外部图片链接展示。

正文支持 Markdown 表格、围栏代码、引用、任务列表、链接与数学公式。行内公式使用 `$…$`，块级公式使用单独成行的 `$$` 包围；预览和公开页使用同一解析器，代码块与转义的美元符号保持原样。首页、列表和搜索摘要省略公式源码，纯公式内容显示“数学公式笔记”。数学排版由浏览器完成，服务器不增加计算依赖。点击“插入图片”后自动压缩并插入 Markdown；本地图片随公开状态控制访问，未发布草稿图片只供所有者读取。原始 HTML 显示为文字；外部图片不直接加载，可下载后自行上传。正文中的远程链接仍可使用。

博客编辑的发布设置可以选择“首页精选”和“置顶文章”；仅已公开内容会展示。友链支持上传可裁剪头像、填写显示顺序（数字越小越前），未设置头像时保留文字占位。个人资料还可更换侧栏背景，使用可调整的 3:1 裁剪并支持恢复默认。

内容管理侧栏提供“导出全部内容”，文章/笔记列表提供单篇导出。下载为 ZIP，包含 UTF-8 Markdown 和 images/ 下的本地图片，相对链接可离线使用；全部导出还包括五类内容、私密草稿、头像和背景，只有登录后可以下载，不含密码或会话。

服务导航和服务健康检查已移除；旧数据库中的服务记录仍保留，不再提供对应功能。会话默认 12 小时，到期需重新登录；退出只撤销当前会话，重设主账号会撤销全部会话。除主账号外可用 `add-account` 添加额外的登录账号，权限与主账号相同，可登录并编辑全部内容；添加账号不影响已有会话。

## RSS 订阅

页脚和页面 head 都不再露出订阅入口，`/feed.xml` 仍可访问，供已知地址的阅读器使用。它输出 RSS 2.0，仅包含最新 50 条公开博客和笔记的标题、摘要、发表日期及独立阅读链接，按发表日期降序排列；不会输出私密内容或未提交草稿。配置实际 `SITE_ORIGIN` 后条目链接随之使用正式地址，无需邮件服务或第三方依赖。

## 本机运行

```sh
python3 server.py account
python3 server.py --port 3080
```

打开 http://127.0.0.1:3080 。账号初始化通过终端输入，密码不会回显；不要把密码放进聊天、命令参数或环境变量。再次执行 `account` 会替换主账号并注销全部会话；`python3 server.py add-account` 在已创建主账号的前提下添加额外的编辑账号，不影响已有会话。`SITE_DB` 可指定数据库路径，默认 `data/site.sqlite3`。

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build.py
```

产物为 `dist/personal-website.tar.gz`，只包含应用、静态文件、部署配置和说明，不含账号、数据库或测试数据。前端无需编译；构建执行 Python 语法验证并打包部署文件。

## 部署配置

`deploy/personal-website.service` 使用专用用户 `personal-site` 运行应用，程序目录为 `/opt/projects/personal-website`，数据库独立放在 `/var/lib/personal-website`。确保数据库目录归该用户且仅其可读写；更新应用时保留数据库。

在 `/etc/personal-website.env` 中按实际访问地址设置 `SITE_ORIGIN`。HTTPS 就绪后，在独立的站点 server 中采用 `deploy/openresty.conf` 的 location 配置，勿覆盖其他服务。现有 OpenResty 在使用 host 网络的容器中运行，应用文件未挂载到该容器；模板将本站页面、静态文件和 API 一并代理到回环服务。头像上传请求允许 1536 KiB，文章/作品封面及统一媒体上传允许 3 MiB；博客、笔记、草稿和个人资料写入请求允许 1 MiB，以容纳完整的 50,000 字符正文及 JSON 转义。其余后端 API 请求仍限制为 64 KiB。应用只监听本机 3080 端口，不开放该端口到公网。OpenResty 配置测试通过后再 reload。

如需初始化或重设服务器上的主账号，或添加额外的编辑账号（需先创建主账号），在服务器终端执行：

```sh
sudo -u personal-site env SITE_DB=/var/lib/personal-website/site.sqlite3 /usr/bin/python3 /opt/projects/personal-website/server.py account
sudo -u personal-site env SITE_DB=/var/lib/personal-website/site.sqlite3 /usr/bin/python3 /opt/projects/personal-website/server.py add-account
```

域名与 HTTPS 未就绪时，可使用 SSH 隧道访问，`SITE_ORIGIN` 设为对应的本机访问地址。部署后另行验证登录、公开与私密内容边界、头像上传，以及服务重启后的持久化。

## 更新与回滚

更新前保留上一份发布包和本站 OpenResty 配置，备份 SQLite 数据库。初始化会增量新增个人资料、封面、草稿和媒体表，可重复执行；不会重写已有内容、账号或个人资料，也不会删除旧服务记录。更新只替换应用和本站配置。需要回滚时恢复上一发布包与配置，保留数据库，执行 OpenResty 配置测试后再重启本站服务与 reload。

## 每日备份与恢复

每天上海时间 04:30 通过 systemd timer 执行 SQLite online backup，错过时间会在下次启动补做；保留最近 7 个日期的备份，同日重跑替换当天备份。备份存于 /var/backups/personal-website，由 personal-site 所有且仅其可读写。完整备份包括账号、全部内容、草稿及图片；在完成并通过 integrity_check 后原子发布，成功后才轮换。此为服务器本地备份；全部内容导出可另外保存到自己的设备。

```sh
install -d -m 0700 -o personal-site -g personal-site /var/backups/personal-website
install -m 0644 deploy/personal-website-backup.service /etc/systemd/system/
install -m 0644 deploy/personal-website-backup.timer /etc/systemd/system/
systemd-analyze verify /etc/systemd/system/personal-website-backup.service /etc/systemd/system/personal-website-backup.timer
systemctl daemon-reload
systemctl start personal-website-backup.service
systemctl enable --now personal-website-backup.timer
systemctl list-timers personal-website-backup.timer
```

需要恢复时，先将选定备份复制到独立临时目录，用 Python sqlite3 执行 integrity_check 并查看内容/图片数量确认选对备份；保留当前库后短暂停止本站服务，再将已核验的备份替换为 SITE_DB 指定文件，设置 personal-site:personal-site、0600，启动服务并核验。不可在运行中的数据库上直接覆盖文件。当前默认数据库为独立文件，若自行启用了 WAL，还须在服务停止后妥善处理旧 -wal/-shm 旁文件，避免带入不属于恢复库的日志。

## 验证入口

- `python3 -m unittest discover -s tests -v`：临时数据库中的 HTTP 功能、旧库增量初始化、正文/媒体访问边界、草稿提交、导出与备份恢复。
- `npm test`：公式、摘要、表格、代码、HTML转义、图片/链接规则，以及草稿恢复与提交回归。
- `python3 tests/browser_fixture.py --seed --port 13082`：仅用于浏览器验收的临时账号与数据库，`--seed` 加入虚构的长文章、七类作品和草稿；不加该选项为空库。退出进程即清理，不能用作部署。
- `python3 tests/deployment_acceptance.py /opt/projects/personal-website`：使用实际安装代码和当前 Python，在独立临时库中验收并重启验证持久化，不修改正式内容。
- 部署和真实浏览器验收结果记录在 artifacts，实体手机体验尚未验证。
